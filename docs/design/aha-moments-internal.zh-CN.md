# 字工厂：Aha Moment 设计文档（内部）

> 受众：游戏设计师、产品设计师。**不是玩家文案。**

## 核心边界

Aha Moment 是设计工具，不是玩家要读到的功能名称、任务列表或路线图。

玩家应该通过游戏行为自己发现变化：按钮第一次出现、资源第一次产生、旧规则被新规则替代、页面尺度突然扩大。玩家界面不显示 `A01–A28`、`Aha`、`Director Mode`、未来章节说明或“你即将发现什么”。

中文玩家尤其避免把设计解释直接写进 UI。不要出现类似：

- “A01 · 机器替我按按钮”
- “NEXT AHA”
- “这是一个 Aha Moment”
- “接下来会解锁城市地图 / Agent / 机器语言”
- “ACT IV 会发生……”

这些内容只属于设计文档和开发调试工具。

## 玩家看到什么

玩家只看到当下世界中自然成立的东西：

1. 尚未发现：完全不存在于玩家界面。
2. 第一次发现：通过行为后自然出现，不提前解释。
3. 已经发现：永久留在界面中；临时资源不足时可以 disabled，但不能消失。
4. 范式替代：只有剧情/机制明确替代旧系统时，旧界面才允许退出。

设计公式：

`hidden → discovered → persistent → intentionally replaced`

## 中文文案原则

中文玩家文案优先使用世界内语言，而不是产品/设计语言。

- 用“工坊资金”，不用“Resource #2”。
- 用“工坊日志”，不用“事件调试器”。
- 用“暂不可用 / 还差 20 字”，不用“未满足 Trigger”。
- 新系统出现时直接让玩家操作，不弹窗解释“这是设计好的惊喜点”。
- 不显示未来系统的灰按钮、锁图标、章节路线图。

## A01–A28 的使用方式

完整 Aha 目录仍由现有设计规格维护：

- `docs/superpowers/specs/2026-09-16-acts-engine-v3-design.md`

该目录用于检查节奏、顺序、反转强度和页面重构，不用于生成玩家可见文案。

## 评审

设计评审可以在本地开发环境使用 Director/Preview 工具检查 A01–A28，但生产玩家部署不得暴露这些入口或复制完整 reveal 文案。

`public/intent.html` 是设计原型源文件，也属于内部评审材料；静态玩家构建不会发布它。
